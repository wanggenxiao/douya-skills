# 电子书（EPUB / MOBI）→ Markdown

> 豆学堂教学版。纯 Python 标准库，**电脑上有 Python 就能跑，什么都不用装**。

## 用途

把 `.epub` / `.mobi` 电子书转成 LLM 友好的 Markdown，保留：
- 标题层级（h1-h6 → `#`-`######`；mobi 源若无 h 标签则无标题层级，见「已知限制」）
- 图片（抽到 `images/`，md 里留相对路径引用）
- 脚注引用（`<sup>` 上标 → `[^N]`）
- 粗体/斜体、有序/无序列表、引用块、分割线
- 书名 + 作者（置于 md 开头）

输出：`<输出目录>/<书名>.md` + `images/` 子目录。

## 关键事实（必读）

**电子书不需要 OCR。** epub 是 zip + XHTML，mobi 是 PalmDB + LZ77 压缩的 HTML，
文字本来就结构化，解包重排即可。
所以本 skill 是**确定性转换**——不存在 MinerU 那种"看着正常实则错了"的问题，
**不需要强制校核流程**，转完抽查一眼排版即可。

**与 MinerU 的分工**：

| 源格式 | 用哪个脚本 | 原因 |
|---|---|---|
| PDF（含扫描件） | `mineru-pdf-to-markdown` skill | 版面锁死/图片化，要 OCR+版面还原+校核 |
| **EPUB** | `scripts/epub_to_md.py` | zip + XHTML，零识别误差 |
| **MOBI** | `scripts/mobi_to_md.py` | PalmDB + PalmDOC LZ77，解出来就是 HTML |
| docx | 直接 Read / 解 XML | 本来就是结构化 |
| azw3 / kfx | 先用 Calibre `ebook-convert` 转 epub 再走本 skill | 亚马逊新私有格式，未实现 |
| HUFF/CDIC 压缩的 mobi | 同上走 Calibre | 罕见，脚本会明确报错 |

## 调用方式

```bash
python "<skill>/scripts/epub_to_md.py" "<书.epub>" [-o "<输出目录>"]
python "<skill>/scripts/mobi_to_md.py" "<书.mobi>" [-o "<输出目录>"]
```

- 纯标准库，任何 Python 3.8+ 都能跑，不需要 venv
- 不传 `-o` 默认输出到 `<书所在目录>/<书名>_epub|` 或 `<书名>_mobi/`（与原件并排）

跑完会打印：书名、图片数、md 字数、标题数、脚注引用数——
**一眼判断有没有转空**（字数几百 = 基本是壳，可能带 DRM；mobi 脚本会主动告警）。

## 输出位置铁律（与 mineru skill 一致）

**转录产物一律放在原电子书同一目录下，与原件并排**（默认行为即正确，别画蛇添足传 `-o` 指别处）。
- ❌ 禁止丢进 `_scratch`——md 是"资料的可读版本"，不是调试中间品
- ⚠ 聊天附件若在 `tmp` 类临时目录，先定位原件真实位置再转（同 mineru skill 的教训）
- 只有原件目录不可写时才退 `_scratch`，并在回复里说明
- 用户明示输出路径时按用户指定

## DRM 提醒

带 DRM 的书（如部分 Kindle/正版渠道加密书）解出来是乱码或空壳，本 skill **不解 DRM**。
识别特征：文件数正常但 md 字数极小、正文乱码。遇到就如实告诉用户"这本带 DRM 转不了"。

## 已知限制

- **mobi 可能没有标题层级**：老 mobi 的 HTML 常用 `<p><b>` 当标题而没有 h1-h6 标签，
  转出来标题数为 0 是**正常现象**（正文无损），不要当成 bug 去硬猜标题（实测误报率极高）
- mobi 的 `first_image_index` 字段常不可靠（实测有书填 0），脚本已改为扫描图片 magic
- 脚注只保留**引用标记** `[^N]`，不自动回填脚注正文（脚注正文在书末"注释"章，会照常转出）
- 跨文件的脚注编号可能重复（每章从 1 重排是常态），不影响阅读
- 复杂排版（诗歌缩进、多栏对照表）会退化成普通段落——语义在、版式简
- 加密/损坏的文件直接报错退出

## 实测记录

**2026-09-26 epub 定版**：《巴拉巴西成功定律》（31 张图）→ 38 spine 全转出，
19.1 万字，96 标题，175 脚注引用，图片零丢失，空标题/脚注粘连已修。

**2026-09-27 补 mobi 支持**：《爆发》（142 文本记录）→ 17.6 万字 + 20 图；
《链接》10周年纪念版（187 文本记录）→ 25.4 万字 + 21 图 + 书末参考文献完整。
两本均无 h 标签（标题数 0 属正常）。PalmDOC LZ77 解压、recindex 图片映射实测通过。

**2026-09-27 晚 修图片错位 bug（用户读书时当场抓包）**：
`extract_images` 里 `recindex += 1` 误放在 `if ext:` 外面——INDX/FLIS 等非图片记录
也占 recindex 编号，导致正文全部图片引用整体错位 N 位（N=首个图片记录前的非图片记录数），
《链接》哥尼斯堡七桥图被配成作者照片。修复：只有图片记录占号。
同时修正 MOBI 头偏移误读：`first_image_index` 正确位置是 r0[112:116]（MOBI 头偏移 96），
此前错读 r0[124:128]（huffman table offset，恒为 0）。

**2026-09-27 深夜 ★★ 混合文件双区问题（用户再次抓包乱字「聊很久」→「聊嚄\uE03E久」）**：
z-lib 的 mobi 常是 **MOBI6 + KF8 混合包**：MOBI6 旧区是给上古设备的**降级副本**
（可能有乱字、无 h 标签），**真实阅读器显示的是 KF8 区**（version 8，标准 XHTML）。
我们此前一直读 MOBI6 旧区——calibre 参照实现解压结果一致，证明乱字在旧区数据本身，
KF8 区同段文字完好。教训极其重要：
- **KF8 boundary 在 MOBI 头偏移 192（r0[208:212]）**，有效则从 boundary 起 16 条记录内
  找第二个 `MOBI` 头，改读 KF8 区；脚本输出会打印「读取区: KF8/MOBI6」
- KF8 区图片引用是 `src="kindle:embed:XXXX"`（**base36** 编码的 recindex），
  MOBI6 区是 `recindex="N"`（十进制），两种都要认
- KF8 区是完整 XHTML：有真 h1-h6（《链接》实测 151 个标题），要剥 `<head>`
  （否则节名"书名页"会污染书名和正文）；书名过滤通用节名（书名页/封面/版权页）
- **「老 mobi 标题数 0 属正常」的旧结论是错的**——那是读了降级 MOBI6 区的症状。
  现在：读到 KF8 区而标题数为 0 才是书本身没标题；读到 MOBI6 区要提示用户旧区可能降级
- 另验证：extra record data flags 在 z-lib 书上是 0xFFFF 填充值，但按"末字节低2位+1"
  剥离末尾的行为本身正确（抽样 20 条记录，剥掉的全是乱码字节，正文零损失）

**2026-09-27 深夜② ★★ 尾部数据两阶段修剪（用户第三次抓包：正文散布 \x00/� 乱码）**：
只按"末字节低2位+1"剥 multibyte 尾巴是**不完整**的——记录末尾还有 **trailing entries**
（变长，7bit varint 编码长度），不剥会被当成压缩指令解析，产生 \x00、PUA、重复字节等乱码
（《链接》KF8 区实测 84 处，每条文本记录末尾一处）。
正确算法（照 kindleunpack 源码实现，拿 `mobi` pip 包解包结果做过原文比对）：
- flags 在**记录偏移 0xF2=242**（不是 258！258 的 0xFFFF 是填充值，此前两次误读都在这）
- `multibyte = flags & 1`；`trailers = flags 高位 bit 中置 2 的个数`（flags>>1 逐位数）
- **先**按 varint 剥 trailing entries（末 4 字节扫描：遇高位清零，否则 num=(num<<7)|(v&0x7F)），
  **再**剥 multibyte 尾巴 (末字节&3)+1
- 每个区（MOBI6/KF8）用**自己头部**的 flags
- 验证：《链接》修剪后 \x00 从 84 → 0，"图的例子很多"等与 mobi 包解出的原文完全一致

**mobi 转换后验收清单（每次必做）**：
1. 看脚本打印的「读取区」：混合文件必须是 KF8；MOBI6-only 的书提示用户旧区风险
2. **三类乱码扫描都为 0**：`\x00`、PUA（\uE000-\uF8FF）、U+FFFD（�）
3. 挑 1-2 处正文图片引用对照原书（图对不对，不能只看数量）
4. 标题数是否合理（社科书通常几十到上百个）
5. 存疑时拿 `mobi` pip 包解包当"标准答案"比对原文（`pip install mobi`，仅比对时需要）
